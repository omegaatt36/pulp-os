# T7/T8 production integration map

Read-only production inspection, 2026-10-06. Scope: R4, R5, R10, R11, R14. Recommendations below are interface proposals, not implemented behavior. T3/T6 interfaces may change while their owners work; currently `fontpack/src` contains reader/missing modules but no preparation/cache module.

## Lifecycle and safe preparation sites

* `kernel/src/kernel/app.rs:285`: `App` lifecycle already receives `&mut KernelHandle` in enter/resume/background. `on_event` receives only context; `draw(&self, &mut StripBuffer)` at line 308 cannot read storage through the supplied interface. Keep draw immutable and limited to prepared font data.
* `src/apps/reader/mod.rs:905`: `background` owns reader mutation plus the kernel handle. `NeedIndex` at 1055 and `NeedPage` at 1109 are concrete sites for blocking metrics lookup and visible glyph preparation. All three success paths currently switch to Ready and dirty the page: previous-chapter last-page scan at 1086, restored-offset search at 1130, ordinary page load at 1140. Each must publish only a fully prepared visible page.
* `src/apps/reader/paging.rs:112`: `load_and_prefetch` reads/copies the actual page buffer, wraps it, decodes images, and computes the next byte offset. It has an early chapter-RAM return at 130 and an empty-file return at 159. Preparation must cover those branches, including reader title/chrome when body is empty. Avoid preparing prefetched text bitmaps as if already visible.
* `kernel/src/kernel/scheduler.rs:174`: normal background runs before render, but input can win `select`; the scheduler then dispatches that event at 185 and proceeds to render at 205. TOC navigation (`reader/mod.rs:1179`) and quick-menu mutations can therefore change visible text after the last background call. A background-only preparation policy does not cover every redraw.
* Smallest reliable cross-app seam: add a preparation operation to `App`/`AppLayer`, dispatch it through `AppManager`, and invoke it with a short-lived handle immediately before rendering the newly visible state. This is an interface proposal; preparation failure must leave a drawable previous/loading/error state and must not publish a partly prepared page. Include boot render (`scheduler.rs:109`, `scheduler_c61.rs:193`) and redraws inside X4 render (`scheduler.rs:323,364,393`), not only the normal main-loop gate. Review the X4 deferred-input redraw path when selecting the exact call sites.
* `src/apps/manager.rs:534`: manager background dispatches active app plus suspended app caching. `draw` at 554 adds loading text, quick menu and button feedback after active app content. Those manager-owned overlays need preparation too. Suspended background work must not evict glyphs pinned for an in-flight render.

## Smallest font interfaces

* `src/fonts/mod.rs:90`: `FontSet` is currently a Copy collection of four static `BitmapFont` references. `font`, `line_height`, `ascent`, `advance`, `draw_char`, `draw_bytes`, `draw_str` are the existing consumption seam (164–224). Retain Latin style selection; use static font `has_glyph(ch)` (`bitmap.rs:108`) to decide whether regular CJK fallback is needed. Never use `resolve` alone for availability: it silently returns ASCII `?` (`bitmap.rs:99`). Missing CJK must resolve to the T3 explicit fallback with the same advance in measure and draw (R4).
* Proposed split: mutable storage-backed metrics/preparation provider during layout; immutable prepared glyph view during draw. Both resolve `(char, style, body/heading size)` with the same decision rule. FontSet can remain a static Latin descriptor; an owned cache should not be forced into static references or a Copy/self-referential FontSet.
* Pack metrics use `u16` advances and signed `i16` bearings (`fontpack/src/lib.rs:51`); existing FontSet advance/draw return `u8` (`fonts/mod.rs:184,194`). Widen integration values or validate bounded conversion explicitly rather than truncate. Pack bitmap offsets are not `BitmapGlyph` flash offsets; draw prepared bitmap slices using pack metrics.
* `build.rs:78,87`: current body sizes are 16/19/23/28/35 px; heading sizes 23/27/32/38/46 px. `fontconv/src/lib.rs:21` includes their union. `fonts::chrome_font()` is always body XSmall (`fonts/mod.rs:64`), while UiFonts tracks the settings UI size (`fonts/mod.rs:22`). CJK heading and chrome must select their corresponding pack size, not the current body pack indiscriminately (R5/R14).
* `reader/mod.rs:556`: `apply_font_metrics` currently uses Latin regular native line height/ascent and HAS_REGULAR to enable proportional layout. Body/heading fallback metrics must be available before deriving layout; any chosen common baseline/line-height policy must be identical in indexing and visible draw. Do not make CJK silently depend on HAS_REGULAR being present.

## Pagination, kinsoku and position

* `paging.rs:20`: wrapping copies FontSet to avoid borrowing all of self while mutating `pg.lines`. Replace with disjoint field borrows/provider references, or finish metrics staging before wrapping. An owned cache loses the current Copy escape hatch.
* `paging.rs:395`: `wrap_proportional` is the single production proportional layout function. UTF-8 branch at 543 measures via `fonts.advance`; ASCII fast path at 600 directly indexes `font.glyphs` for spaces/word runs and recomputation at 660. All width calculations must share provider resolution if fallback can serve absent Latin glyphs too. Preserve existing style markers, quote indents, image reservations and whitespace behavior.
* Current Unicode overflow breaks at last space or directly before the overflowing scalar (`paging.rs:576`); it has no prohibited line-head/tail checks. R10 requires legal scalar-boundary break candidates for mixed CJK/Latin and prohibited heads `，。、？！）」』】`, tails `（「『【`. Moving a break must not discard or duplicate punctuation or marker bytes. The fixture includes supplementary scalar 𠮷; do not use 16-bit codepoints.
* `paging.rs:169`: next page offset is old offset plus wrap's consumed raw-byte count. `preindex_all_pages` at 219 reuses wrapping without a handle; it must gain metrics preparation access or prepared metric staging. Bitmap-only visible-page caches are insufficient for full-chapter indexing. `scan_to_last_page` at 251 and restore search (`reader/mod.rs:1110`) also repeatedly lay out pages; share exactly the same metrics and break policy.
* `reader/mod.rs:198`: page offsets are raw buffer/file byte offsets; line spans use u16 byte starts/lengths inside the 8192-byte page buffer. `text_len` (`paging.rs:373`) preserves incomplete UTF-8 tails; decoding replacement policy must leave the original buffer bytes unchanged. Continue returning raw consumed byte offsets for malformed subparts and supplementary scalars (R11).
* Navigation (`paging.rs:271,295`) re-enters NeedPage/NeedIndex; bookmarks and resume use chapter plus byte offset (`reader/mod.rs:625,651,676,686`). Restore selects the page whose next offset exceeds the saved byte position. This preserves text anchoring only if indexing/restoration use the same provider and kinsoku rules. Font identity/layout cache invalidation is T9; do not duplicate it in T7/T8.

## T8 surface inventory

* Heading: spans already carry style flags (`reader/mod.rs:179,191`) and draw changes style on markers (`reader/mod.rs:1668`); route Heading through the correct regular CJK heading-size fallback while Latin retains existing heading style.
* TOC: `reader/mod.rs:1504` bypasses FontSet and draws directly with `fonts::body_font` at 1510, including inverse selected-row foreground. Prepare only visible TOC labels plus marker; use the shared fallback and keep foreground-aware drawing. Event visibility uses `font_line_h`, whereas current draw uses native body font height; shared prepared metrics must define one visible-row rule.
* Book title: `reader/mod.rs:1407` draws `display_name` via `draw_chrome_text` (`788`) and static chrome font. It is drawn even while body loading, so body-Ready preparation alone misses title fallback. OPF title assignment is in `reader/epubs.rs`; title/file buffers retain T4 UTF-8 truncation behavior.
* UI labels: `widgets/bitmap_label.rs:12,54,123` hardcodes static BitmapFont for labels and dynamic labels; `draw_label` calls static `draw_aligned` at 142. Accept an immutable prepared text/font view (including measure/alignment and foreground) rather than teaching each label to read SD.
* Files title/name rows: `apps/files.rs:453,502`; directory/title reload occurs in background at 378–397. Home bookmark titles: `apps/home.rs:505,542`; Settings labels/values: `apps/settings.rs:431,462,473`. These apps hold UiFonts and already have background hooks. Manager propagates sizes/chrome (`manager.rs:578`); include quick menu (`widgets/quick_menu.rs:293`), button feedback, and kernel loading indicator (`manager.rs:558`) when collecting visible labels.

## Storage adapter and borrow constraints

* `fontpack/src/reader.rs:13`: `ReadAt` owns positioned reads with u64 offset, exact-fill semantics and associated error. `PackReader::open` at 76 accepts reader plus known file length; it keeps its source and validates header before lookups.
* `kernel/src/kernel/handle.rs:105,126`: `read_app_subdir_chunk` and `file_size_app_subdir` are the existing narrow firmware operations for installed packs. `with_sync_reader_app_subdir` at 50 provides a scoped closure bridge. Adapter needs checked u64→u32 positioning and repeated short-read handling; zero read before exact fill is a recoverable font I/O error. Do not reuse EPUB `read_full` blindly: it reads root files and takes u32 offsets.
* `kernel/src/drivers/storage.rs:57`: each `op_read_chunk` opens, seeks, reads and closes a file; subdirectory read at 485 also takes the storage RefCell guard. No persistent file handle is exposed to apps. This is sufficient correctness surface for T7/T8; optimizing repeated opens is outside this mapping.
* A PackReader owning an adapter that borrows `&mut KernelHandle` cannot live in ReaderApp between callbacks. Open/use it within preparation, release handle borrow, and retain only owned cache/metadata. Split reader/page/cache borrows explicitly; do not hold a cache glyph slice while adding another glyph. Draw can borrow prepared glyph slices because it does not mutate cache. Release all SD/storage guards before entering the strip renderer; C61's strip source calls only immutable AppLayer draw (`scheduler_c61.rs:60`).

No production edits or tests were made for this mapping.

## Addendum: owned staging with the proposed T6 PageCache

The proposed T6 `PageCache<S, B>` API is supplied by the controller; no cache module was present on disk during this follow-up inspection. The smallest integration keeps `FontSet: Copy` unchanged and adds an app-owned CJK state alongside it. The descriptor used by layout borrows that state; it does not own storage or perform I/O.

1. **Metrics stage:** own a fallibly allocated, capacity-limited Vec of `(pixel_size, char, Metrics)` in the app. Collect only characters absent from the selected Latin style, sort/deduplicate by `(pixel_size, char)` (immutable lookup uses binary search), then open each required pack within the handle callback and fill metrics using `PackReader::find` or `missing_glyph_metrics`. Clear/reuse the Vec for each input buffer. A PAGE_BUF-sized buffer can contain at most PAGE_BUF scalar occurrences, including maximal-subpart replacements, so PAGE_BUF is a safe cap on unique text keys collected using the same style-marker scanner. This is a maximum, not a reason to eagerly allocate 8192 records: reserve fallibly for the actual candidate count and keep a lower configured budget if needed; report an explicit preparation-capacity failure. Header/role metrics are separate small owned values. The metrics stage contains no bitmap bytes and no borrowing PackReader.
2. **Layout descriptor:** propose `LayoutFonts<'a> { latin: FontSet, metrics: &'a MetricsStage }`, with `advance(char, Style) -> Result<u16, MissingPreparedMetric>` and line-height/ascent methods. Preserve `font(style) -> &'static BitmapFont` for existing ASCII batches when the static glyph is valid. For non-ASCII, resolve static `has_glyph` first, otherwise resolve staged pack metrics by active role/size. Missing staged entries are programmer/preparation failures, distinct from a font lacking a character. Missing pack glyphs have already staged the explicit square metrics. If keeping infallible advance for minimal wrapping churn, make construction validate every candidate first and represent an absent key as an explicit assertion/error before calling wrap, never an SD lookup or silent question mark.
3. **Wrapping ownership:** copy the existing FontSet local, finish `self.cjk.stage_metrics(k, &self.pg.buf[..n], fs)` first, then create the borrowed descriptor from `self.cjk.metrics`; pass it with disjoint `&self.pg.buf` and `&mut self.pg.lines` to `wrap_proportional`. It need not borrow ReaderApp as a whole. Return raw consumed byte count unchanged. English-only buffers yield no fallback candidates and use existing static advances/batches with zero pack open/read; this preserves the English layout pin.
4. **Visible bitmap cache:** after final line spans are known, collect fallback characters only from visible text spans (plus title/visible overlays prepared separately), and call T6 `PageCache::prepare` for each size. Draw uses immutable `PageCache::get`; drawing cannot reach PackReader or metrics-staging I/O. A PageCache prepared from one PackReader represents one pack/size, so body and heading need separate owned cache instances when both are visible. Reader chrome adds its own size; deduplicate roles sharing a pixel size if convenient, but never reuse a body cache for heading metrics. Bound the sum of those cache capacities by the chosen per-app budget. Use owned caller storage (e.g. fallibly allocated Vec/boxed slices for slots and bytes), with explicit owned-state reset on app exit/replacement (apps remain resident, so on_exit must release the storage); no leaked slices, self-reference, or shared mutable global cache.
5. **Indexing:** the chapter text is already owned in `epub.ch_cache` (BigBuf, maximum 98304 bytes; `reader/mod.rs:93,246`), but contains no font metrics. `preindex_all_pages` (`paging.rs:219`) copies each PAGE_BUF window into `pg.buf`, so change it to take `&mut KernelHandle` and stage metrics per copied window before its existing wrap call. Discard/reuse each metrics stage as it advances; do not prepare bitmaps for index-only windows. Likewise restored-offset/last-page scans can request layout-only loads and prepare bitmaps once for the final visible page. A simple `load_and_prefetch(k, prepare_visible: bool)` or separate `layout_loaded_buffer(k)` / `prepare_current_page(k)` methods makes this distinction concrete without duplicating layout.

The same regular fallback decision applies in both descriptors and cache draw. Static Latin bold/italic retain their existing glyphs; absent CJK in either style uses regular CJK body, and Heading uses regular CJK heading. Per-app owned stages/caches can be allocated lazily and reused; preparation must fail explicitly when allocation/capacity limits are reached.
